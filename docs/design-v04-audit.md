# pi-todone v0.4 设计审计请求

## 背景

pi-todone 是 pi coding agent 的扩展，解决"AI 长自主任务偷懒"（提前停、空转、随便 done、不拆任务）。已有 v0.3.1 发布（npm + GitHub CI）。

## 问题数据（近 3 天会话语料：767 会话文件 / 5977 工作单元）

- 用户侧 176 次"偷懒/敷衍"类话语；"别偷懒"多为睡眠前预防指令
- deepseek-v4-flash 仅 8% 工作单元使用 todo；subject 平均 16 字符（pro 模型 44.9）
- 真实 E2E：AI 标 completed 无证据被 block 后，试错 8+ 种格式仍失败，最后放弃并删除任务
- 卡点时不重规划 todo，硬闯或停摆

## 已实现（v0.3.1，通过 36 断言 + 6 场景 mock E2E + CI）

1. **格式闸**（tool_call block）：todo 标 completed 必须 metadata.evidence（state/runnable/effect 三类），宽容归一化（单对象/字符串/缺 kind/裸命令自动修复），完全无法归一化才 block
2. **证明点协议**（agent_end 注入）：有 pending → 注入"证明进展|说明卡点|继续"三选一；停滞 N 轮 → 卡点报告（终态通知后静默，防循环）；完成项 → 注入 spawn fresh reviewer 语义验证
3. **创建义务**：单元 ≥5 工具调用且未拆 todo → 注入拆 todo（小任务豁免）
4. **L1 常驻**：before_agent_start 追加编译期常量义务摘要（纯静态，缓存安全）
5. 防循环：停滞检测/指数退避/同文本去重/交互静默/幂等
6. skill 知识层：~/.agents/skills/pi-todone/SKILL.md

## 设计哲学（已定，不审计）

- 一个工具做一件事：pi-todone 只做 todo 义务；结构规范在 skill；目标理解在决策审计层
- 能强制的做进工具（硬闸），不能强制的放规范层，语义理解留给 AI 与审计
- 证明义务在 AI 侧：插件只校验格式不验证真实性；语义靠独立 subagent（防共谋）
- 缓存安全：L1 必须编译期常量；动态内容走消息通道

## v0.4 待审计方案

### 脚手架理论（本次审计核心）

文本规范（skill/L1/注入）在长任务中必然偏移忘记（数据：8% 使用率、E2E 试错）。解法：**把"思考义务"编码为"填写义务"**——动作点门禁（block）不依赖 AI 记忆：

| 机制 | 层级 | 对抗 |
|---|---|---|
| evidence 格式闸（已有） | 动作点 block | 随便 done |
| **创建字段门禁**：create 必须 acceptance 非空 / estEvidence ∈ 枚举 / 根节点 userIntent 非空 / 非根 parentId 存在 | 动作点 block | 忘记维度 |
| 树完成传播：父 completed 时子（parentId=自己）全 completed，否则 block | 动作点 block | 目标假完成 |
| 返工计数：同任务 completed→pending 回退 ≥3 次 → 注入重规划/停机 | 软校验+注入 | 循环不收敛 |
| 依赖就绪/引用存在性（blockedBy/parentId 指向存在） | 软校验（提示不 block） | 跳步/错引用 |
| skill：结构三原则 + 验收循环表达 | 文本规范 | 语义质量（被门禁锚定） |

### 已砍掉的设计（防伪门禁）

- verdict 证据类型（subagent 裁决转述可谎报，语义判不了，多道手续）
- verifyBy/until 声明门禁
- 结构语义校验（acceptance 质量、启发式判定）——必误报

### 关键取舍点（请重点审计）

1. **创建字段门禁是否过度**：无直接数据证明"列了但缺维度"（数据只有"不列"8%）。辩护士：字段存在性对抗的是"忘记"，不是"质量差"；创建是低频动作（每任务一次），block 试错成本 1-2 轮可控
2. **树完成传播是否必要**：防"目标假完成"（概括性偷懒的机械版），但未直接观察到"父 completed 子 pending"案例
3. **返工计数阈值与语义**：completed→pending 回退即计数，是否误伤"合法返工"（验收失败重做是正常流程）
4. **门禁数量**：3 个 block 门禁 + 2 个软校验，是否会积累成"表单地狱"，伤害小任务体验（创建义务已豁免小任务不列 todo，但列了的都被约束）
5. **是否存在更简方案**：比如只保留 evidence 格式闸 + 创建字段门禁，砍树传播和返工计数？或全部软校验不 block？

## 审计输出要求

- 对每个取舍点给出 approve / reject / modify 判定 + 理由
- 指出方案的过度工程点（如果有）
- 指出方案的遗漏点（如果有）
- 最终判定：这个方案够优雅吗？最小化吗？
- 输出为结构化清单，简洁（不超过 600 字）
